# Слежка за Авито (`scripts/avito_watch.py`, `avito/`, «Слежу на Авито» на главной)

_С 18.10.2026._ Неделями одна и та же выдача руками: «как сегодня дела?» → страницы → карточки → «а все карточки
смотрел, не только первую страницу?». Теперь это стоящая слежка: mini раз в день смотрит выдачу, открывает каждую
новую карточку, проверяет правила по тексту и фото и звонит **только** о подходящих (или подешевевших подходящих).
В каждом уведомлении и на главной — охват: сколько страниц, объявлений, карточек и фото.

## Из чата

С ноутбука любая команда сама уходит на mini по ssh: слежки и их состояние живут только там.

```
python3 scripts/avito_watch.py list                       # слежки, последний прогон, охват
python3 scripts/avito_watch.py show iphone-17-pro         # файл слежки + подходящие
python3 scripts/avito_watch.py stop iphone-17-pro         # остановить (start — вернуть)
python3 scripts/avito_watch.py add pns-kit --title "PNS, размер L" \
    --url "https://www.avito.ru/moskva?q=pns+джерси" --size L --region Москва --delivery \
    --rule "Одежда PNS (Pas Normal Studios), оригинал" --rule "Размер L по бирке или описанию" \
    --price-max 15000                                      # новая слежка (--replace — переписать)
python3 scripts/avito_watch.py run --force [--watch id] [--max-cards 3]   # прогон сейчас (на mini)
ssh mini tail -40 movies/logs/avito-watch.log
```

`--url` — выдача Авито (город в пути, лучше категория с фильтрами: меньше мусора). `s=104` (сначала новые)
дописывается сам. `--title-must` / `--title-not` — регэкспы по заголовку выдачи, `--price-min/max` — отсев до
карточки. `--region` — город продавца (`sellerAddressInfo.locality` карточки); `--delivery` — другой город годится,
если есть Авито Доставка. `--min-reviews` по умолчанию 1: без отзывов не предлагать.

## Как устроен прогон

launchd `cc.bodywithoutorgans.avitowatch` (`deploy/install-avito-watch.sh`, ставится **с ноутбука**: везёт `av.py`
скилла avito) стартует в 06:30, 10:30, 14:30 и 18:30, но работает раз в день: поздние запуски (`due`) — только если
утренний упёрся в блок, капчу или оставил очередь.

1. **Браузер** — видимое окно Chrome for Testing на mini (браузер Playwright, `~/Library/Caches/ms-playwright`),
   профиль `~/.avito-watch/profile`, CDP 9222, через `av.py` скилла avito (`~/.claude/skills/avito/av.py` на mini —
   копия с ноутбука). Python — отдельный venv `~/.local/avito-venv` с playwright 1.63. Плагин avito-mcp здесь не
   используется: `scan_new_listings`/`get_price_history` требуют Supabase, а `get_listing` не отдаёт ни рейтинга
   продавца, ни фото. Дедуп и история цены — свои, в `data/avito-watch.json`.
2. **Сеть.** Авито (176.114.120.0/21) идёт с mini мимо VPN, с домашнего IP (`deploy/direct-routes.txt`) — того же,
   что у ноутбука. Блок от прогона выжигает адрес и для ручного поиска, поэтому: выдача 8–15 с между страницами,
   карточки навигацией не чаще раза в 60–90 с, не больше `max_cards` (12) за прогон. Фото с `*.img.avito.st` идут
   через VPN, им всё равно.
3. **Выдача** по дате, страница за страницей; останавливается на странице, где всё уже знакомо (на первом прогоне —
   на пределе `pages`). Все новые id ложатся в состояние без вердикта — это и есть очередь, так что блок посреди
   прогона ничего не теряет.
4. **Отсев по выдаче** (заголовок, цена) — без карточки. Карточки — дефицит: Qrator режет их раньше выдачи.
5. **Карточка**: в коде — снято / в резерве, число отзывов продавца (`sellerInfo`; рейтинг стоит вплотную к числу,
   «4,8 22 отзыва» иначе читается как 822), город. Остальное — `claude -p --model opus --tools Read` по
   `avito/JUDGE.md` и правилам слежки, с фото карточки (galleryInfo.media, до 12, в `~/.avito-watch/cards/<id>/`).
   «Фото просмотрено» в отчёте — это число вызовов Read модели по этим файлам, а не число скачанных.
   Вердикт `match` — все правила выполнены, `no` — хоть одно нарушено, `unsure` — нарушений нет, но что-то не видно;
   звонит только `match`, `unsure` видно на главной числом.
6. **Уведомление** (`notify.py` → `avito_items`, свежесть 24 ч, тап → главная): одно на прогон, если есть
   подходящие или подешевевшие подходящие; блок/капча/сбой — одно в день (`avito-block:<дата>`).

**Капча.** Прогон её не решает и не пытается. Сначала до 30 с ждёт, пока Chrome сам пройдёт «проверку
безопасности» Qrator (она мелькает при каждом холодном старте). Если в заголовке осталось «проблема с IP» — шлёт
уведомление «Авито: прогон не прошёл» и **ждёт человека** до `AVITO_CAPTCHA_WAIT_MIN` (45) минут, проверяя вкладку
раз в 15 с: пазл пройден — прогон продолжается с того же места. Не дождался — повтор в следующем слоте.
Окно живёт и после прогона: в plist `AbandonProcessGroup`, иначе launchd убивает Chrome вместе с группой процессов
агента. 19.10.2026 так и было: уведомление о капче пришло, а окна на mini уже не было.

Как добраться до окна без монитора: дома — `open vnc://192.168.1.40` (Общий экран включён, вход — пользователь mini);
вне дома — `ssh -N -L 9333:127.0.0.1:9222 mini`, в Chrome ноутбука `chrome://inspect` → Configure → `localhost:9333` →
inspect на вкладке avito.ru: DevTools показывает страницу вживую, слайдер тянется мышью. 9333, а не 9222: на ноутбуке
9222 может быть занят своим Chrome скилла avito.

## Файлы

- `avito/watches/<id>.json` — слежки (**только на mini**, в `.gitignore` и в исключениях `deploy.sh`: репозиторий
  публичный, покупки — личное). Поля: `searches[{url,pages}]`, `title_must`, `title_not`, `price_min/max`, `size`,
  `region`, `delivery`, `min_reviews`, `rules[]`, `max_cards`, `active`.
- `data/avito-watch.json` — состояние (mini): по слежке `seen` (id → заголовок, цена, история цены, вердикт),
  `queue`, `runs` (30 последних отчётов с охватом); `events` для уведомлений; `lastRun`.
- `avito/JUDGE.md` — промпт проверки карточки. Описание продавца в нём объявлено данными, не инструкцией.
- `GET /api/avito` — `avito_watch.public()`: слежки, последний прогон, до 6 подходящих.
